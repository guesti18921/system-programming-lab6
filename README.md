# Лабораторная работа №6
## Межпроцессное взаимодействие через системные очереди сообщений POSIX IPC

**Цель работы:** изучить передачу сообщений между процессами через очереди POSIX, управляемые ядром Linux.

**Среда:** Linux/WSL, Python 3, библиотека posix_ipc.

## Программы

- `ipc_sender.py` создаёт очередь `/sys_prog_queue` и отправляет пять сообщений.
- `ipc_receiver.py` получает сообщения и после пятого закрывает и удаляет очередь.

## Основной эксперимент

Сначала был запущен отправитель:

    python3 ipc_sender.py

После его завершения очередь продолжала существовать. Это проверено командой:

    ls -l /dev/mqueue/

В списке находилась очередь `sys_prog_queue`.

Затем был запущен приёмник:

    python3 ipc_receiver.py

Он получил сообщения с номерами от 1 до 5 и удалил очередь из операционной системы.

## Исследовательский эксперимент

При запуске исходного приёмника первым появилась ошибка: очередь ещё не существовала.

Затем строка подключения была изменена на:

    mq = posix_ipc.MessageQueue(QUEUE_NAME, flags=posix_ipc.O_CREAT)

Изменённый приёмник создал пустую очередь и остановился в ожидании сообщений. Отправитель был запущен во втором терминале.

## Объяснение ожидания приёмника

Приёмник ожидал внутри вызова `mq.receive()`, потому что очередь была пустой. Этот вызов блокирующий: ядро Linux переводит поток в состояние сна, ожидающего поступления сообщения.

Терминал не возвращал приглашение командной строки, поскольку программа ещё не завершилась. При этом поток не проверял очередь непрерывным циклом, поэтому ожидание не загружало процессор на 100%. Процессорное время могло использоваться другими потоками и процессами.

Когда отправитель поместил сообщение в очередь, ядро разбудило поток приёмника. Планировщик предоставил ему процессорное время, и вызов `mq.receive()` вернул сообщение. После получения пятого сообщения программа закрыла и удалила очередь, затем завершилась.
